The problem

      
Remote development breaks when the link does

      
On hotel Wi-Fi, a VPN or a tethered phone, the usual tools fail in the worst way: they take your work down with them.

    

    

      
Remote-SSH
The editor freezes
Your files live on the server, so every keystroke waits on the network. Lose the link and you lose the editor.

      
ssh host cmd
The command dies
A two-hour training run is tied to one SSH session. One dropped packet too many and it's gone.

      
rsync + ssh
Everything by hand
Copy, ssh, run, copy the results back, remember what changed. Again, after every edit.

    

    
devsync does all of it in one step, and survives the drop.

  






  

    

      
Features

      
Feels local. Runs remote.

      
One command sends your changes, runs on the remote in the matching folder, streams the output and brings results back.

    

    

      
Edit at full speed
Files stay on your machine. Any editor, any tool, no lag, even with no network at all.

      
Commands outlive the connection
Jobs run detached on the remote. A dropped link only delays the output; the exit code is always collected.

      
Transfers resume
Interrupted uploads and downloads continue where they stopped, and only changed files move.

      
Results come back
Output, exit code and files your command generated come home. Your own edits are never overwritten.

      
Zero remote setup
Just SSH. devsync uploads its own small static agent, checks it, and keeps it up to date.

      
Works with coding agents
A Claude Code hook routes tests, builds and installs to the remote while the agent edits locally. devsync setup claude

    

  






  

    

      
How it works

      
Short sessions, nothing to lose

      
devsync never holds a long-lived connection you could lose. Every exchange is a quick SSH session.

Quick start

      
Running remotely in a minute

      
All you need is SSH access to the remote machine.

    

    

      
01
Connect a project
cd my-project
devsync init me@gpu-box:~/my-project
Works with any host in ~/.ssh/config. An empty folder pulls the remote's code first.

      
02
Run on the remote
devsync exec -- pytest -x
devsync exec -- python train.py
Changes are sent first. Output streams back; the exit code is yours.

      
03
Keep it in sync
devsync watch
devsync setup claude
Push on every save, and let Claude Code run commands remotely.
