SSH breaks when the Wi-Fi does

The usual way to work on a remote machine hangs everything on one long SSH connection. On hotel Wi-Fi, a VPN or a train, that connection drops, and it takes your work with it.

The idea: short trips, not one long call

devsync never keeps a connection open. Each step is a separate, quick SSH session that's safe to retry, and your command runs on its own on the remote. A drop just means waiting a moment.

Start in a minute

All you need is SSH access to the machine.

01

Connect a folder

devsync init me@gpu-box:~/project

Any host from ~/.ssh/config works. An empty folder pulls the remote's code first.

02

Run on the remote

devsync exec -- python train.py

Your changes go first. Output streams back and the exit code is yours.

03

Keep it in sync

devsync watch

Or install the VS Code extension and let auto sync do it on every save.
